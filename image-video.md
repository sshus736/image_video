# Image Video Project Documentation

## 1. Project Overview

This project is a local AI storyboard and image-frame generation app.

The user enters a short story idea. The app expands it into a full story, splits it into time segments, generates frame-level image prompts, generates each frame through a `gpt-image-2` compatible image API, and saves generated frames under `output/`.

Current build status:

- Frontend: React 19 + TypeScript + Vite + Tailwind CSS.
- Backend: Express local proxy in `server/index.js`.
- Text model: OpenAI-compatible chat completions, default `gpt-5.5`.
- Image model: OpenAI-compatible image API through a relay, default `gpt-image-2`.
- Video composition: disabled in this build. The app keeps generated image frames and can be extended later with ffmpeg.

## 2. Runtime Architecture

The project uses a browser frontend plus a local backend proxy.

```text
Browser UI
  |
  | fetch /api/*
  v
Vite dev proxy or same-origin production server
  |
  v
Express backend: server/index.js
  |
  +-- Text API: /chat/completions
  |
  +-- Image API: /images/generations, fallback /chat/completions
  |
  +-- Output files: /output/*
```

During development, Vite runs on port `5175` and proxies `/api` and `/output` to the backend on port `3001`.

In production, `server/index.js` serves `dist/`, exposes the same API routes, and serves generated output files.

## 4. Main User Workflow

The main workflow is controlled by `src/App.tsx`.

1. User submits a synopsis and generation settings from the UI.
2. `generateFullStory()` calls `/api/story-expansion`.
3. `generateStoryboardScript()` creates scene templates, frame prompts, one unified background image, and a shared character mask.
4. The app stops at `background-ready` and asks the user to confirm the unified background.
5. After background confirmation, the app generates a character turnaround reference sheet with front, side, and back views.
6. The app stops at `character-ready` and asks the user to confirm the character reference.
7. After character confirmation, every frame is generated by inpainting the same character onto the same background.
8. The backend saves frame PNGs under `output/imgN/frame_00001.png`, `frame_00002.png`, etc.
9. The frontend displays generated frames and stores project metadata in localStorage.

Generation is intentionally conservative:

- Frames are generated serially in the current flow to reduce relay rate-limit or cooldown issues.
- Character frames must use the unified background inpaint path; the batch flow does not silently fall back to direct full-image generation because that causes background drift.
- Character frames also use a confirmed three-view character reference sheet to reduce identity, clothing, and body-shape drift.
- Consecutive failures are capped to avoid a long stuck run.
- Base64 image data is not persisted in localStorage; only metadata is saved.

## 5. Environment Variables

Create `.env` from `.env.example`.

```env
PORT=3001

OPENAI_API_BASE=https://serve.wzjself.org/v1
OPENAI_API_KEY=your_text_api_key
TEXT_MODEL=gpt-5.5

IMAGE_API_BASE=https://serve.wzjself.org/v1
IMAGE_API_KEY=your_image_api_key

TEXT_API_BASE_FALLBACK=https://api.deepseek.com/v1
TEXT_API_KEY_FALLBACK=your_fallback_key
TEXT_MODEL_FALLBACK=deepseek-v4-flash
```

Notes:

- `IMAGE_API_BASE` must include `/v1`.
- `IMAGE_API_KEY` is used only by the backend.
- `OPENAI_API_BASE` / `OPENAI_API_KEY` are used for text generation.
- Fallback text API variables are optional.
- Do not commit `.env`.

## 6. API Calling Details

### Text Generation

Frontend calls:

```text
POST /api/chat
POST /api/story-expansion
```

Backend forwards text requests to:

```text
POST {TEXT_API_BASE}/chat/completions
```

The backend injects the configured text model (`TEXT_MODEL`) and can fall back to `TEXT_API_BASE_FALLBACK` if the primary provider returns retryable server errors.

### Image Generation

Frontend calls:

```text
POST /api/images
```

Backend default upstream call:

```text
POST {IMAGE_API_BASE}/images/generations
```

Request body:

```json
{
  "model": "gpt-image-2",
  "prompt": "image prompt",
  "n": 1,
  "size": "1024x1024"
}
```

The backend also supports a fallback to:

```text
POST {IMAGE_API_BASE}/chat/completions
```

This fallback is important for relay stations that expose image models through chat completions. The backend normalizes both response styles into:

```json
{
  "data": [
    {
      "b64_json": "...",
      "url": "...",
      "saved_path": "/output/imgN/frame_00001.png"
    }
  ]
}
```

Supported upstream image response formats:

- Standard image response: `data[0].b64_json`
- Standard image response: `data[0].url`
- Chat response with Markdown data URL: `choices[0].message.content = "![image](data:image/png;base64,...)"`

### Inpaint

Frontend calls:

```text
POST /api/inpaint
```

Backend forwards multipart form data to:

```text
POST {IMAGE_API_BASE}/images/edits
```

This is used by the background separation path when a fixed background and mask are available. If inpaint fails, the frontend falls back to direct image generation.

### Fetch Image Proxy

Frontend and backend may call:

```text
POST /api/fetch-image
```

This downloads an allowed external image URL and returns a data URL. It is used to avoid CORS, URL expiry, and mixed-content issues.

Allowed hosts include OpenAI/CDN hosts and `wzjself.org` domains. The proxy rejects non-image content and images larger than 20 MB.

## 7. Data Model

Core types live in `src/types/storyboard.ts`.

### Shot

Represents one generated frame.

Important fields:

- `id`: stable frame id.
- `index`: frame index.
- `segmentIndex`: owning story segment.
- `imagePrompt`: current prompt used for image generation.
- `baseImagePrompt`: original generated prompt before user edits.
- `imageUrl`: generated image data URL or URL.
- `referenceImageUrl`: optional reference image for image-to-image flow.
- `maskImageUrl`: optional mask image for inpaint.
- `imageStatus`: `idle`, `loading`, `done`, or `error`.

### StorySegment

Represents one time segment of the expanded story.

Important fields:

- `index`
- `timeRange`
- `description`
- `shots`

### StoryboardProject

Represents a saved local project.

Important fields:

- `userPrompt`
- `fullStory`
- `segments`
- `shots`
- `backgroundImageUrl`
- `backgroundPrompt`
- `createdAt`

## 8. Key Frontend Files

### `src/App.tsx`

Owns the main state machine:

- `idle`
- `expanding-story`
- `generating-script`
- `background-ready`
- `generating-character`
- `character-ready`
- `generating-images`
- `done`
- `error`

It coordinates story expansion, prompt generation, frame generation, cancellation, project saving, and UI state.

### `src/lib/openai.ts`

Despite the filename, this file is the frontend API and generation workflow layer. It calls the local backend, not upstream APIs directly.

Major responsibilities:

- Story expansion client.
- Scene template generation.
- Segment and frame prompt generation.
- Background generation.
- Mask generation.
- Direct image generation.
- Inpaint generation.
- Prompt rewrite for user edits.
- Project and settings localStorage persistence.

### `src/components/PromptForm.tsx`

Input form for synopsis, style, FPS, duration, image size, and variation settings.

### `src/components/ShotCard.tsx`

Displays one generated frame, prompt text, editing controls, retry/regenerate actions, and image upload/reference options.

### `src/components/SettingsPanel.tsx`

Settings UI for model, FPS, duration, style, variation, and size.

### `src/components/HistoryPanel.tsx`

Displays saved local projects.

## 9. Key Backend Files

### `server/index.js`

Single Express server for:

- Loading `.env`.
- Serving production `dist/`.
- Serving generated files under `/output`.
- Proxying text model calls.
- Proxying image model calls.
- Normalizing image responses.
- Retrying transient upstream errors.
- Handling cooldown/rate-limit errors.
- Saving image frames to disk.

Important routes:

```text
GET  /api/health
POST /api/chat
POST /api/story-expansion
POST /api/images
POST /api/inpaint
POST /api/fetch-image
POST /api/compose-video   returns 410 in current build
```

## 10. Output Files

Generated frames are saved under:

```text
output/img1/
output/img2/
...
```

Frame names are ordered when `frameName` has a numeric prefix:

```text
frame_00001.png
frame_00002.png
frame_00003.png
```

The backend also returns `saved_path`, which the frontend can use as a stable local URL:

```text
/output/img7/frame_00001.png
```

## 13. Known Limitations

- Video composition is currently disabled. `/api/compose-video` returns HTTP 410.
- The image relay may rate-limit or cooldown. The backend retries transient errors but does not retry hard model cooldown exhaustion.
- Image-to-image support depends on relay behavior. The backend sends reference images to `/images/generations` first and only falls back to `/chat/completions` if necessary.
- Large base64 images can make API payloads heavy. The app avoids saving base64 image data to localStorage.
- `.env.example` may need to be updated if the deployment relay URL changes.

## 14. Maintenance Notes

- Keep upstream API keys only in `.env`.
- Keep frontend API calls pointed at `/api/*`; do not call upstream model providers directly from browser code.
- Prefer changing provider-specific behavior in `server/index.js`, not in UI components.
- Keep `src/types/storyboard.ts` as the source of truth for shared data shape.
- Treat `output/` and `dist/` as generated artifacts.
- After modifying generation behavior, run both build checks and a small `/api/images` smoke test.
